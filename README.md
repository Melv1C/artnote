# ArtNote

ArtNote is a [TanStack Start](https://tanstack.com/start) application for exploring artworks through detailed notes. It uses Prisma on a PostgreSQL database (Prisma Accelerate in production, a Docker Postgres locally) and Better Auth for authentication, and is deployed on Vercel.

## Setup

1. Use the correct Node.js version:

   ```bash
   # If you have nvm installed
   nvm use

   # Or install Node.js 24 manually
   # The project requires Node.js 24 (see .nvmrc)
   ```

2. Install dependencies with [Bun](https://bun.com) (version pinned through `packageManager` in `package.json`). Bun is only the package manager and script runner; the app itself runs on Node.js:

   ```bash
   bun install
   ```

   Dependency lifecycle scripts only run for packages listed in `trustedDependencies` (currently just `esbuild`). Prisma's postinstall is skipped on purpose; the client is generated by `db:setup`, `check`, `prisma:migrate` and `vercel-build`.

3. Environment variables: `bun run db:setup` (next step) writes `.env` from `.env.example` on its first run, with a database and dev port of its own for this checkout. `.env` and `.env.local` are loaded into `process.env` for server code (`.env.local` wins). The variables are validated in `src/lib/env.ts`. Image uploads need a real `BLOB_READ_WRITE_TOKEN`: put only that variable in `.env.local`. Don't `vercel env pull` into `.env.local`, because its `PRISMA_DATABASE_URL` would point the app and the `db:*` scripts at the shared database.

4. Start the local database (Docker), create this checkout's database, apply migrations, generate the Prisma client and seed sample data:

   ```bash
   bun run db:setup
   ```

   Sign in with `admin@example.com` or `user@example.com`, password `artnote-dev-password`. `PRISMA_DATABASE_URL` also accepts a `prisma+postgres://` Accelerate URL; `db:setup`, `db:reset` and the seed refuse to run against a non-local database.

5. Run the development server:
   ```bash
   bun run dev
   ```
   The app is served at `BASE_URL` from `.env`.

## Scripts

- `bun run dev` – Vite dev server with TanStack Start.
- `bun run build` – production build (client assets and the Nitro server output in `.output/`; on Vercel, Nitro emits `.vercel/output`).
- `bun run start` – serve the production build locally (`node .output/server/index.mjs`).
- `bun run vercel-build` – used by Vercel: `prisma generate`, `prisma migrate deploy`, then `vp build`.
- `bun run check` – everything CI runs: Prisma generate and validate, `vp check` (Oxfmt, Oxlint and the TypeScript type check), `vp test` (Vitest), knip and the build (regenerates `src/routeTree.gen.ts`).
- `bun run fix` – format and apply lint fixes.
- `bun run db:setup` / `db:seed` / `db:reset` / `db:down` – local database: set up, re-seed, recreate this checkout's database, stop the shared container.

## Deployments

Vercel deploys from Git:

- `main` → staging, at https://artnote-git-main-melvyns-projects-316f75ef.vercel.app (Preview environment).
- `production` → production. Only the Release workflow moves this branch; don't push to it.
- Any other branch or PR → its own preview.

Feature branches open PRs into `main`. Staging and PR previews share the preview database, and `vercel-build` runs `prisma migrate deploy` against it.

To release, tag a commit that is on `main` and push the tag:

```bash
git tag v1.2.0 origin/main
git push origin v1.2.0
```

`.github/workflows/release.yml` force-pushes the tagged commit to `production`, and Vercel deploys it. To roll back, push a tag on an older commit, or use Instant Rollback in Vercel.

## Toolchain

[Vite+](https://viteplus.dev) (`vp`) is the toolchain: Vite for dev and build, Vitest for tests, Oxlint for linting and Oxfmt for formatting, all configured in `vite.config.ts`. `vp check` formats, lints and type-checks in one pass. knip covers unused code. See `docs/adr/0008-vite-plus-toolchain.md`.
