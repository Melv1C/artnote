# ArtNote

ArtNote is a [TanStack Start](https://tanstack.com/start) application for exploring artworks through detailed notes. It uses Prisma (with Prisma Accelerate) on a PostgreSQL database and Better Auth for authentication, and is deployed on Vercel.

## Setup

1. Use the correct Node.js version:

   ```bash
   # If you have nvm installed
   nvm use

   # Or install Node.js 24 manually
   # The project requires Node.js 24 (see .nvmrc)
   ```

2. Install dependencies with [Bun](https://bun.com) (version pinned through `packageManager` in `package.json`). Bun is only the package manager and script runner; the app itself runs on Node.js:

   ```bash
   bun install
   ```

   Dependency lifecycle scripts only run for packages listed in `trustedDependencies` (currently just `esbuild`). Prisma's postinstall is skipped on purpose; the client is generated by `prisma:generate` / `prisma:migrate` / `vercel-build`.

3. Set up environment variables:

   ```bash
   # Copy .env.example to .env and update the values for your environment
   cp .env.example .env
   # Edit .env with your local configuration

   # Pull development environment variables from Vercel
   vercel env pull .env.local
   ```

   `.env` and `.env.local` are loaded into `process.env` for server code (`.env.local` wins). The variables are validated in `src/lib/env.ts`.

4. Apply database migrations (this also generates the Prisma client):

   ```bash
   bun run prisma:migrate
   ```

5. Run the development server:
   ```bash
   bun run dev
   ```
   The app will be available at http://localhost:3000.

## Scripts

- `bun run dev` – Vite dev server with TanStack Start.
- `bun run build` – production build (client assets and the Nitro server output in `.output/`; on Vercel, Nitro emits `.vercel/output`).
- `bun run start` – serve the production build locally (`node .output/server/index.mjs`).
- `bun run vercel-build` – used by Vercel: `prisma generate`, `prisma migrate deploy`, then `vite build`.
- `bun run lint` / `bun run type-check` – ESLint + Prettier, and TypeScript.

## Folder overview

- `src/routes/` – TanStack Router file-based routes. Pages live next to server routes under `src/routes/api/` (REST endpoints, auth handler, Vercel crons). `src/routeTree.gen.ts` is generated by the Vite plugin.
- `src/router.tsx` – router setup (default not-found and pending components).
- `src/features/` – feature modules (components, server functions, hooks).
- `src/components/`, `src/hooks/`, `src/lib/`, `src/schemas/` – shared UI, hooks, libraries and Zod schemas.
- `prisma/` – Prisma schema and database migrations.
- `package.json` – Project scripts and dependencies.

## Server code conventions

- Data loading and mutations use `createServerFn` server functions, called from route loaders or event handlers.
- Modules that must never reach the browser (`src/lib/prisma.ts`, `src/lib/auth.ts`, etc.) import `@tanstack/react-start/server-only`. The build fails if one is pulled into client code.
- Dashboard server functions use `dashboardAccessMiddleware` (`src/lib/auth-functions.ts`). Server functions are public HTTP endpoints, so every private read and mutation must check the session itself.

## TypeScript

TypeScript 7 (the native compiler) runs `bun run type-check` through the `@typescript/native` alias. `typescript` is aliased to `@typescript/typescript6`, so tools that need the TypeScript JS API (typescript-eslint) keep working.
