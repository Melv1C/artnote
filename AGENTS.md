# ArtNote: agent guide

ArtNote publishes scholarly notices about paintings for a French-speaking (Belgian) audience. Public visitors browse and read notices; admins write them in `/dashboard`.

Stack: TanStack Start (React 19, Vite, Nitro), TanStack Router (file routes), Prisma 7 on PostgreSQL, Better Auth, Tailwind 4 + shadcn, Tiptap. Hosted on Vercel. Single app, not a monorepo.

## Local setup

Needs Bun (package manager and script runner), Node 24 (runtime) and Docker.

```bash
bun install
cp .env.example .env    # defaults point at the local Docker database
bun run db:setup        # start Postgres, apply migrations, generate the Prisma client, seed
bun run dev             # http://localhost:3000
```

If port 3000 is taken, run `BASE_URL=http://localhost:3100 bun run dev --port 3100`. Better Auth rejects sign-ins when `BASE_URL` doesn't match the origin.

Seeded accounts (password `artnote-dev-password`):

| Email               | Role                     |
| ------------------- | ------------------------ |
| `admin@example.com` | admin, sees `/dashboard` |
| `user@example.com`  | user                     |

The seed also creates 2 places, 3 artists and 3 artworks (2 published, 1 draft).

Image and avatar uploads go to Vercel Blob and fail without a real `BLOB_READ_WRITE_TOKEN`. Put only that variable in `.env.local`, never a `vercel env pull`: `.env.local` wins over `.env`, and its `PRISMA_DATABASE_URL` would point everything at the shared database.

## Commands

| Command                                | Use                                                                                                    |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `bun run check`                        | Everything CI runs: lint, Prisma generate and validate, build (regenerates the route tree), type-check |
| `bun run lint`                         | ESLint and Prettier check                                                                              |
| `bun run lint:fix`                     | Fix lint and formatting                                                                                |
| `bun run type-check`                   | TypeScript 7 only; needs a generated Prisma client and a fresh route tree, which `check` provides      |
| `bun run db:setup`                     | Start the database, migrate, generate, seed. Safe to re-run.                                           |
| `bun run db:seed`                      | Re-run the seed (idempotent)                                                                           |
| `bun run db:reset`                     | Delete the local Docker volume and set up from scratch                                                 |
| `bun run db:down`                      | Stop the database                                                                                      |
| `bun run prisma:migrate --name <name>` | Create a migration after editing `prisma/schema.prisma`                                                |

There are no automated tests. To verify a change, run `bun run check` and commit any `src/routeTree.gen.ts` change it makes (CI fails on an uncommitted one), then run the app and check the change in a browser, signed in with a seeded account when needed.

## Database

- `PRISMA_DATABASE_URL` selects the connection (`src/lib/prisma-client.ts`). A `postgresql://` URL connects directly through `@prisma/adapter-pg`; a `prisma+postgres://` URL goes through Prisma Accelerate (Vercel).
- Schema: `prisma/schema.prisma`. The client is generated into `src/generated/prisma` (gitignored) and imported from `@/generated/prisma/client`.
- `status`, `role` and place `type` are plain strings; the allowed values live in Zod enums in `src/schemas/common.ts`.
- Vercel runs `prisma migrate deploy` on every build, previews included, so a migration reaches the shared database as soon as a branch deploys.
- Only run migrations, resets and seeds against the local Docker database. `db:setup`, `db:reset` and the seed refuse a non-local host (`scripts/assert-local-db.ts`).

## Code layout

- `src/routes/`: pages and layouts. `src/routes/api/**` holds only the Better Auth handler, the Vercel crons and the public analytics beacon; app data never goes through REST. `src/routeTree.gen.ts` is generated by the Vite plugin during `dev`, `build` and `check`; commit it with the route change.
- `src/features/<feature>/`: `actions/` (server functions and server-only queries), `components/`, `hooks/`.
- `src/lib/`: env validation (`env.ts`), Prisma, Better Auth, permissions, SEO.
- `src/schemas/`: Zod schemas per entity.
- `src/components/ui/`: shadcn components and the rich text editor.

## Conventions

- All app data goes through `createServerFn` server functions in `src/features/<feature>/actions/`: route `loader`s call them, and so do React Query hooks for client-driven reads (search, selectors). Mutate through server functions, then call `router.invalidate()` or invalidate the query.
- Modules that must stay on the server import `@tanstack/react-start/server-only`.
- Server functions are public HTTP endpoints. Every private read and every mutation declares its guard as middleware from `src/lib/auth-functions.ts`: `dashboardAccessMiddleware` (admin, `artwork: ['manage']`) for dashboard code, `requirePermission({ <resource>: [<action>] })` for a specific permission, `requireAuth` for a user's own data. Read the user from `context.user`, never from a second session lookup.
- User administration calls Better Auth's server API (`auth.api.*` with `getRequestHeaders()`), never the browser `authClient`.
- Parse Prisma results through the Zod schemas in `src/schemas/`.
- User-facing text is French; code, identifiers and commits are English.
- Commits follow Conventional Commits (`feat:`, `fix(scope):`, `chore:`).

## Branches and releases

- Branch from `staging` as `feat/*` or `fix/*` and open the PR against `staging`. CI only lets `staging` target `main`.
- Releases squash-merge `staging` into `main` as `release: DD MM YYYY — <title> (#PR)`.
